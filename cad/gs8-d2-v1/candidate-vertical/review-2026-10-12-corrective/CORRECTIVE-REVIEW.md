## How it was reviewed

1. **Reproduction.** A clean detached worktree of the delivered commit on the user's Windows CAD interpreter (CPython 3.12.14, CadQuery 2.6.1, OCP 7.8.1.1), every CAD job through the shared `run_locked.py` lock: inspect and `--check` generators, all 39 candidate test files (526 tests), the r7 suite, a fresh compact-Kowa export (twice), and the documented main batch on that re-export with a row-level comparison against the committed reports.
2. **Four review dimensions**, each by an independent reviewer: check integrity (every check, gate, tolerance, accepted set and test between `bdfd44f` and `1b59395`), geometry (STEP diffs and probes on the committed exports), publication (secrets, paths, licences, sizes, wording) and electrical (power, J2, BOM, wiring).
3. **Adversarial verification.** A separate verifier per dimension tried to refute each finding, set the confirmed severity and listed what the reviewer missed. Severities below are the verifier's.

## Reproduction result

**What reproduced.** No headline engineering claim of the delivered commit failed to reproduce. From a fresh Windows re-export (manifest `8bfc3efa`, sources identical to the committed manifest's) the documented batch gave, row for row and with 0 status differences: main audit 633 pass / 1 fail / 32 info (the only failure is the Pi/cooler source overlap, 79.902671 mm³); harness 30 / 12 / 20 with the same 12 failing rows; check-scope 36 / 0 / 14; plenum 49 / 0 / 21; outlet context 4 / 0; print checks 161 / 0 / 7. Re-derived figures: 130/130 bonded-stub rows pass with a minimum `worst_gap` of 0.106 mm against 0.100 mm; hot path minimum cut 509.999996 mm² (pass within the pre-existing 0.002 mm² tolerance); cold 420.0 mm²; hot branch series 575.2 mm²; production counts compact 9 rows / 10 prints, original 10 / 11. Two Windows exports were byte-identical (106/106 files plus the manifest). `make_corrected_pi.py` reproduced byte for byte. The r7 suite passed (82/82; 73 OK; release audit pass with 56 open gates). The package PDFs equal the repository copies.

**What did not reproduce.**

- The committed evidence was produced on linux-x86_64 (`bdfd44f` was win32-amd64). Windows cannot rebuild the git-ignored mesh caches (38 of 45, 38 of 45 and 39 of 46 bound mesh files differ; triangulation and order differ, not only the last digit). The package supplies Linux caches for compact Kowa only. Hence `export_cache.py status`, `review_docs_audit.py --check`, `reconcile_review_evidence.py --check`, `make_coverage_vertical.py --check` and `test_coverage_gates` cannot pass on Windows.
- `structural-review/update_concealed_vent_structure.py --check` fails on Windows on one zero-valued coordinate (1.67e-16 against 1.69e-16) compared as an exact string.
- 10 candidate test files fail on any platform (stale manifest-bound records, stale pins, new lint violations; register REP-3). The delivered software-check receipt covered a selected subset only.
- Not re-run for time: the Fujinon and original-storage main audits and their scope/plenum/outlet reports, the coupon generators, the structural PDF, the guide build and renders. Their committed reports bind their manifests and current verifier sources, nothing more.

**Cross-platform limits.** Same-platform determinism holds. Cross-platform byte identity does not: STEP files differ in float formatting, STL and mesh JSON in triangulation and order. The committed Linux STEP/STL/mesh bytes cannot be regenerated on Windows, so the review-and-fix commit does not re-export (a re-export would change every output byte and binding).
